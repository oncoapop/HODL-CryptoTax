## 2024-10-26 - Secure SQLite DB initialization against TOCTOU race conditions
**Vulnerability:** In `init_db()` in `src/db.py`, the code removed the existing database file and then allowed `sqlite3.connect` to implicitly create it with default permissions. There was also a Time-of-Check to Time-of-Use (TOCTOU) vulnerability where a malicious actor could create a symlink or malicious file between the `os.remove()` and the subsequent database connection, potentially intercepting or altering the sensitive tax data database. Additionally, default permissions could allow unauthorized users to read the database.
**Learning:** SQLite database initialization needs to be secure, particularly when storing sensitive financial information. By explicitly creating the file with restricted permissions (`0o600`) using `os.open(..., os.O_CREAT | os.O_EXCL, ...)` and failing securely if the file already exists (despite the preceding `os.remove`), we mitigate TOCTOU vulnerabilities and ensure the file is private to the application owner.
**Prevention:** Always use `os.open` with `os.O_CREAT | os.O_EXCL` flags and strict permissions (e.g., `0o600`) to pre-create sensitive local databases or files securely. If catching `FileExistsError` after a presumed removal, explicitly raise an error rather than passing silently to avoid masking race condition exploits.
